# Network engineering: before and after

This local hardening pass improves generation safety and verification without changing the model-first architecture or adding runtime dependencies. It implements the confirmed high-priority findings from the supplied review. It does not implement the entire proposed feature roadmap.

Baseline: v1.1.1, commit `5a05aab0751b37cc533083a8460bf61d6ccf9c8f`. After: the improved working tree, recorded before committing. Runs used Windows and Node 24.15.0 on October 8, 2026 in America/Bogota (the evidence timestamps are UTC). No push, deployment or external publication was performed.

## What changed and why it matters

| Contract | Before | After |
|---|---|---|
| Invalid model → `build` / `config` | Build could exit 0 with validation errors; config bypassed analysis. | Both validate before writing and fail without configuration output. |
| Diagnostic artifacts | Broken models could produce normal config bundles. | `build --allow-invalid` produces reports without configs; a failed gate still exits nonzero. Existing configs in the destination are refused. |
| Required unknown ping | Informational diagnostic allowed successful validation. | Quality gate is INCONCLUSIVE; validation/config/build fail. Rendering remains available for troubleshooting. |
| Unknown fields / malformed input | Typos were warnings; structure checking could mutate missing interfaces. | Unknown fields are errors; explicit relaxed discovery allows warnings. Structural errors stop semantic analysis without mutation, including errors beyond the diagnostic display limit. |
| CLI contract | Unknown/missing flags could be ignored. | Invalid flags, missing values, unexpected arguments and incompatible escape hatches fail. JSON validation includes the modeled quality gate. |
| Device identity and outputs | IDs became hostnames and filenames without enough constraints. | Safe IDs, reserved-name and case-collision checks, optional separate hostname, control-character rejection, path containment and existing link checks. |
| Imported commands | Unsupported lines retained credential-bearing values and could be re-emitted. | Retained unsupported lines become quarantine markers without values. `extraConfig` is omitted from every generated configuration and shareable diff. |
| Credentials | Full config text appeared in HTML and documentation. | Credential fields become placeholders by default. Explicit `--include-secrets` enables restricted configuration output while HTML/Markdown/reports/diffs stay redacted. |
| Configuration persistence | IOS and ASA appended `write memory`. | Candidate commands end without saving. Instructions require observed verification before saving separately. |
| Unsupported CLI profiles | Explicit NX-OS/other profiles could receive IOS or ASA commands. | Unsupported CLI profiles fail validation; the generator returns a non-executable unsupported preview. |
| Example artifacts | Regeneration depended on contributors remembering every file. | All eight diagrams regenerated; a deterministic synchronization check runs in CI. |

The original healthy networking, import, diff, ASA, VPN, IPv6 route, routing-metric, STP and HSRP tests continue to pass. The intentionally broken lab still reports its faults.

These changes intentionally tighten compatibility: previously accepted unknown fields or unsafe IDs must be corrected; required unknown tests must be resolved; redacted credentials must be supplied before a lab configuration is applied; raw `extraConfig` no longer contributes commands. Verification used the original 1.1.1 metadata; subsequent release preparation updates it to 1.1.2 without changing the compared runtime behavior.

## Socket viewer finding

The exact gateway/severity DOM-XSS paths reported by Socket were already escaped in the checked-out v1.1.1. The historical revision `cff5cb1` was vulnerable. We verified this distinction instead of counting the old exploit as newly fixed by this pass.

An isolated headless Edge test runs hostile embedded data through each real viewer version. It opens the subnet inspector and renders diagnostics and diff messages.

| Viewer version | Attack executed | Injected elements / event attributes | Gateway retained as literal text | Severity classes constrained |
|---|---|---|---|---|
| Older vulnerable `cff5cb1` | Yes | 1 / 3 | No | — |
| Baseline v1.1.1 `5a05aab` | No | 0 / 0 | Yes | No |
| Local improvements | No | 0 / 0 | Yes | Yes |

The new viewer inserts gateway details using DOM text nodes and selects status/severity classes from fixed tokens. Permanent tests execute the viewer's rendering code, and the browser check confirms the payload remains visible as text without executing. The current browser run records no JavaScript errors. [Browser evidence](hardening-comparison/viewer-browser.json).

This establishes behavior for the tested payloads and versions. Socket's external warning has not been re-audited or cleared; nothing was published to trigger that process.

## Skill behavior comparison

An independent read-only review compared the same three scenarios. This is a qualitative instruction review, not a benchmark of agent reliability across models.

| Scenario | Before | After |
|---|---|---|
| Quick OSPF question | Direct answers already supported. | Still answers directly without a model or long report. |
| Required ping result is unknown | Zero-error instructions could imply successful verification. | Reports INCONCLUSIVE; configuration generation is blocked; diagnostic rendering remains available. |
| Missing production facts and a `.pkt` request | Native project support was unclear; lab configs were described as ready to paste. | Explicit `.pkt` limitation; lab artifacts and assembly instructions; production configs remain candidates pending evidence. |

The revised instructions shorten activation metadata, distinguish quick/lab/audit workflows, preserve existing authorization, separate intended/modeled/observed state, require positive controls before claiming isolation, and document simulation limitations. Packet Tracer and IOS references now explain credential placeholders and verification before persistence.

Independent code review found two defects in the first patch: broad text redaction could rewrite an ID equal to a password, and the diagnostic limit could hide structural errors in relaxed mode. Both were reproduced, fixed, and added to the permanent regression suite. It also identified the pre-existing unsupported-platform fallback, which is now blocked.

## Verification limits and follow-up work

- Locally verified: all 47 tests, eight synchronized diagrams, the Edge attack comparison, clean `git diff --check`, and all 20 relative file links across `SKILL.md` and the 17 references. Skill name and the 288-character description meet the checked discovery constraints; metadata/version/repository remain consistent.
- The generic skill-creator Python validator could not run because PyYAML is absent. Its allowed-key list also omits the pre-existing Claude Code `argument-hint`, which this portable skill retains. No dependencies were installed to accommodate that validator.
- CI now covers Windows and Ubuntu with Node 22 and 24. Those remote jobs have not run; local evidence covers Windows/Node 24 only.
- No real network device or Packet Tracer instance was tested. Model success is not observed connectivity, firmware compatibility, or an assurance that a production change is safe.
- Redaction covers known structured credential fields and the tested imported/embedded paths. Free text and infrastructure details still require review before sharing. Filesystem checks do not promise protection against a hostile process racing output writes.
- TCP/UDP flow assertions, IPv6 traces, richer import coverage, change/rollback plans, capability/version registries, live simulator integration, secret-manager resolution, static TypeScript checking and website dependency scanning remain follow-up work.

The measured improvement is enforcement of previously missing safety contracts while preserving all existing toolkit scenarios. The supplied qualitative scores were not re-scored as if they were benchmark measurements.
